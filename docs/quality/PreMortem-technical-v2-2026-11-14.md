# Pre-Mortem Analysis: SGRT 技术报告 technical-v2

**Review date:** 2026-11-14  
**Scope:** GitHub Pages 预览发布前的技术报告重构；不包含产品注册、真实设备控制或临床评价。

## Tigers（真实风险）

| 风险 | 等级 | 缓解动作 | 责任人 | 截止 |
|---|---|---|---|---|
| 把教学 R0 演示误读成真实设备或临床能力 | Launch-blocking | 首屏、每章边界和证据页同时保留“合成示例/模拟接口/体模台架”说明；检查否定式表述 | 报告负责人 + 质量官 | 发布前 |
| 拆页导致旧实验链接或脚本失效 | Launch-blocking | `legacyAnchors` 映射、跨页 fragment 检查、6 个页面真实浏览器加载与交互检查 | 前端/报告负责人 | 发布前 |
| 旧版 v0.3.0 被覆盖或与 v2 混入同一提交 | Launch-blocking | 保留 `technical/index.html`；只暂存 v2、检查器、测试、入口与文档；不执行 `git add .` | 报告负责人 | 提交前 |
| GitHub Pages 只部署 `main`，预览分支推送后看不到新版 | Launch-blocking | 验证 Actions 的 `deploy-pages` 触发分支；合入/推送 `main` 后等待部署并访问公开 URL | 发布负责人 | 发布时 |
| 传感器、标定、配准和时延数值被当成设备规格 | Fast-follow | 所有实验显示“教学参数/非厂商算法/非临床阈值”；证据页列出全文/摘要/厂商来源限制 | 技术作者 | 发布后 30 天 |

## Paper Tigers（被认为严重但当前不构成本次阻塞）

- **“必须一次迁移全部旧实验的动画”**：本次目标是重新组织阅读主线并保留高价值交互意图；旧页完整保留，v2 以可验证的教学交互为主，后续可按验收反馈增加。
- **“需要引入前端框架才能维护”**：当前站点是静态、离线可读、无构建依赖；原生 HTML/CSS/JS 更适合 GitHub Pages 和审计。
- **“移动端必须显示全部复杂图上细节”**：允许复杂图表局部横向查看；关键结论和主交互必须在窄屏可读，但不要求每个装饰性标注同时可见。

## Elephants（需要继续观察）

- 读者是否把“系统总览节点”当作正式软件模块，而不是教学抽象。缓解：每章边界和节点详情明确“教学抽象，不是软件接口”。
- 临床协作者是否能在不阅读全部工程细节的情况下找到“能回答/不能回答”。缓解：每章固定结论卡，证据页按问题组织。
- 后续新增证据时，是否会把 Inference 自动升格为 Fact。缓解：证据字段保留 `status`，正文标记与来源编号一起审查。

## Launch-Blocking Action Plan

1. **医疗边界检查**：逐页搜索真实设备控制、临床阈值、绝对性能暗示；保留 R0 声明和合成示例标签。完成标准：没有新增临床结论。
2. **链接与脚本检查**：`python tools/check_report.py` + `python -m pytest` + 本地 HTTP 浏览器检查；验证六个章节、15 个索引和旧锚点。完成标准：全部通过。
3. **发布隔离检查**：只 stage `technical-v2/`、检查器、测试、根入口和本次文档；确认旧技术页未被覆盖。完成标准：`git diff --cached --stat` 无研发线无关文件。
4. **Pages 验证**：推送 `main` 后等待 `deploy-pages` 成功，访问 `https://happyhq.github.io/alignrt-sgrt-report/technical-v2/`，确认 HTTP 200、标题和交互正常。完成标准：公开 URL 可读。

## 当前结论

在医疗边界、断链、提交隔离和公开 URL 验证完成前，不把 v2 标记为正式替代版；当前定位为可访问的预览版。
